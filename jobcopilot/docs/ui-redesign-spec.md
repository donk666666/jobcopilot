# JobCopilot UI/UX 品牌化升级设计文档

## 概述

对 JobCopilot 前端进行全量品牌化升级，建立统一的深色视觉语言，打磨交互细节。范围覆盖全局框架（侧边栏、配色、字体）、5 个功能页面（仪表盘、JD 分析、简历优化、求职信、投递管理）、以及全局组件。

---

## 一、设计系统 (Design Tokens)

### 1.1 配色系统

**背景层级（深靛蓝系）**

| Token | Hex | 用途 |
|---|---|---|
| `--bg-deepest` | `#0b0a1a` | 侧边栏、页面底色 |
| `--bg-card` | `#13102e` | 卡片、表格、输入框背景 |
| `--bg-hover` | `#1c1845` | 行悬停、菜单项悬停 |
| `--bg-elevated` | `#242055` | 对话框、下拉菜单、弹出层 |
| `--bg-input` | `#0f0d24` | 输入框专用底色 |

**Accent（金/琥珀）**

| Token | Hex | 用途 |
|---|---|---|
| `--accent` | `#f0b90b` | 主强调色：按钮、选中态、链接 |
| `--accent-hover` | `#f5cc3a` | 按钮悬停、交互点亮 |
| `--accent-subtle` | `rgba(240,185,11,0.15)` | 标签背景、分割线、选中行底 |
| `--accent-glow` | `rgba(240,185,11,0.25)` | 卡片悬停光晕、发光效果 |

**文字色**

| Token | Hex | 用途 |
|---|---|---|
| `--text-primary` | `#e8e4f0` | 正文、标题 |
| `--text-secondary` | `#9690b8` | 描述、副文本、图标 |
| `--text-muted` | `#6b6588` | 占位符、禁用态、弱化信息 |

**语义色**

| Token | Hex | 用途 |
|---|---|---|
| `--color-success` | `#34d399` | 高匹配度、已 Offer |
| `--color-warning` | `#f59e0b` | 中匹配度、面试中 |
| `--color-danger` | `#f87171` | 差距点、低匹配度、已拒绝 |
| `--color-info` | `#60a5fa` | 待投递、初筛中 |

**边框 & 分割线**

| Token | Hex | 用途 |
|---|---|---|
| `--border-subtle` | `#1c1845` | 卡片边框、表格行线 |
| `--border-input` | `#2a2560` | 输入框边框 |
| `--border-focus` | `#f0b90b` | 聚焦态边框 |

### 1.2 排版系统

```css
--font-sans: 'Inter', 'Noto Sans SC', -apple-system, sans-serif;
--font-mono: 'JetBrains Mono', 'Fira Code', monospace;

/* 标题层级 */
--text-h1: 24px / 1.3 / 700;
--text-h2: 20px / 1.3 / 600;
--text-h3: 16px / 1.4 / 600;
--text-h4: 14px / 1.4 / 600;

/* 正文 */
--text-body: 14px / 1.6 / 400;
--text-body-sm: 13px / 1.5 / 400;
--text-caption: 12px / 1.4 / 400;
```

### 1.3 间距系统

4px 递增：`4, 8, 12, 16, 20, 24, 32, 40, 48, 64`

### 1.4 圆角

| 元素 | 值 |
|---|---|
| 卡片 | `12px` |
| 按钮 | `8px` |
| 输入框 | `8px` |
| 标签/徽章 | `6px` |
| 下拉菜单 | `8px` |
| 模态框 | `16px` |
| 进度条/迷你图 | `4px` |

### 1.5 阴影

```css
--shadow-card: 0 1px 3px rgba(0,0,0,0.4);
--shadow-elevated: 0 4px 16px rgba(0,0,0,0.5);
--shadow-glow: 0 0 20px var(--accent-glow);
```

### 1.6 动效规范

| 类型 | 时长 | 缓动 |
|---|---|---|
| 微交互（hover/focus） | `150ms` | `ease-out` |
| 过渡（tab 切换、展开） | `250ms` | `ease-in-out` |
| 页面进场 | `300ms` | `ease-out` |
| 加载动画 | 循环 | `ease-in-out` |
| 退场 | `200ms` | `ease-in` |

## 二、全局框架

### 2.1 侧边栏

**现有问题：** 颜色过黑（`#1a1a2e`），红色 logo 有压迫感，导航选中态不明显。

**改动：**

- 侧边栏宽度保持 220px（从 200px 微调），底色改为 `--bg-deepest`
- Logo 区：
  - "JobCopilot" 字号 22px，颜色 `--accent`（金色），weight 700
  - 副标题 "AI求职助手" 字号 12px，颜色 `--text-muted`
  - 底部加一条金色细线（`1px solid rgba(240,185,11,0.2)`）
- 导航项：
  - 每个 44px 高，8px 圆角，左右 margin 8px，项目间 gap 4px
  - 默认态：文字 `--text-secondary`，图标同色
  - hover 态：背景 `--bg-hover`，文字 `--text-primary`
  - 选中态：背景 `--accent-subtle`，文字 `--accent`，左侧加 3px 金色竖条指示器（`border-left: 3px solid var(--accent)`，圆角）
  - 图标尺寸 20px，与文字间距 10px
- 侧边栏底部：
  - 后端状态指示器：一个小圆点（4px）+ "服务在线"/"服务离线"文字
  - 颜色：在线 `--color-success`，离线 `--color-danger`
  - 固定在侧边栏底部，padding 16px

### 2.2 主内容区

- 背景色改为 `--bg-deepest`，去除原先的浅灰色 `#f5f7fa`
- 内边距保持 24px
- 页面标题（h1/h2）颜色 `--text-primary`，副标题 `--text-secondary`

### 2.3 全局组件规范

**卡片（el-card 覆写）：**
- 背景 `--bg-card`，边框 `1px solid --border-subtle`，圆角 12px
- header 区域底部有细分割线，padding 16px 20px
- body padding 20px
- hover 态（shadow="hover" 的卡片）：`box-shadow: var(--shadow-glow)`，边框色变亮

**按钮：**
- 主按钮（primary）：背景 `--accent`，文字 `#0b0a1a`（深色保证对比度），hover 时 `--accent-hover`
- 次按钮（default）：背景透明，边框 `--border-input`，文字 `--text-secondary`，hover 时边框和文字变亮
- 文字按钮（text）：文字 `--accent`，hover 背景 `--accent-subtle`

**输入框：**
- 背景 `--bg-input`，边框 `--border-input`，文字 `--text-primary`
- 聚焦态：边框 `--border-focus`，外发光 `0 0 0 3px rgba(240,185,11,0.15)`
- placeholder 颜色 `--text-muted`

**标签（el-tag）：**
- 默认 tag：背景 `--accent-subtle`，文字 `--accent`，边框无
- success/danger/warning/info 分别用对应语义色的 15% 透明度底 + 对应文字色
- 圆角 6px，字号 12px

**表格（el-table）：**
- 背景 `--bg-card`，边框 `--border-subtle`
- 表头背景 `--bg-deepest`，文字 `--text-secondary`，字号 12px，大写
- 行间线 `1px solid --border-subtle`
- hover 行背景 `--bg-hover`
- stripe 行背景 `rgba(255,255,255,0.015)`

**对话框/抽屉（el-dialog）：**
- 背景 `--bg-elevated`，边框 `--border-subtle`，圆角 16px
- 标题文字 `--text-primary`
- 蒙层 `rgba(0,0,0,0.6)`

**加载骨架屏（el-skeleton）：**
- 背景渐变动画：从 `--bg-card` 到 `--bg-hover`
- shimmer 效果（css animation keyframes）

## 三、页面设计

### 3.1 仪表盘 Dashboard

**现有问题：** 四张功能卡片视觉权重一样；统计卡片信息密度低、占空间大；缺乏个性化入口感。

**改动：**

**欢迎横幅（页面顶部）：**
- 宽幅区域，深靛蓝渐变背景（`linear-gradient(135deg, #13102e, #1c1845)`）
- 大标题："早上好/下午好/晚上好，萧仁科"（根据时间动态切换），字号 24px，weight 700，颜色 `--text-primary`
- 下方金色小字概括今日状态，如"你有 3 个岗位等待投递 · 平均匹配度 78 分"
- 右侧放置一个微妙的几何装饰图案（SVG，金色线条，低透明度）

**功能卡片（Bento Grid 布局）：**
- 4 张卡片改为不对称 Grid：
  - 第一行：JD 分析（占 2/3 宽） + 求职信（占 1/3 宽）
  - 第二行：简历优化（占 1/3 宽） + 投递管理（占 2/3 宽）
- 每张卡片：
  - 大图标（32px），颜色 `--accent`，底部有透明金色圆圈背景
  - 标题 16px / 600，副标题 13px / `--text-secondary`
  - hover 态：边框金色光晕（`box-shadow: 0 0 20px rgba(240,185,11,0.15)`），卡片微微上浮 2px
  - 点击跳转到对应页面
- JD 分析卡片加一个 "最近分析" 小字提示（如"上次分析了：字节跳动 AI 产品经理"）

**投递看板管道（替换原统计卡片）：**
- 横向管道，6 个状态从左到右：待投递 → 已投递 → 初筛中 → 面试中 → 已 Offer → 已拒绝
- 每段宽度按实际数量比例分配，颜色从弱到强渐变
- "待投递"段带脉冲动效（呼吸光晕），暗示"这里需要行动"
- 管道上方左侧：总投递数 + 数字大字，右侧：平均匹配度（金色数字）
- 管道下方每个状态标注具体数字

**快速开始指南（替换原 Steps）：**
- 改为水平三列卡片：① 分析 JD → ② 优化简历 → ③ 生成求职信
- 每列带步骤编号（大号金色数字）、标题、一行说明
- 卡片间用虚线箭头连接
- 点击任意卡片跳转到对应页面

### 3.2 JD 智能分析 JDAnalyzer

**现有问题：** 左右 50:50 比例不合理；加载态单调；结果展示缺乏层次。

**改动：**

**布局调整：**
- 左右比例改为 40:60（输入区:结果区）
- 输入区顶部新增"JD 示例"可展开折叠面板（el-collapse），内含 2-3 条示例 JD 供快速体验

**输入区：**
- textarea 高度 20 行，背景 `--bg-input`
- 底部栏：左侧显示 "Few-shot + JSON Schema 输出"（capsule 小标签，透明底金色边框），右侧"开始分析"按钮
- "开始分析"按钮放大，金色背景 + sparkle 图标（使用 el-icon 的 MagicStick）

**分析过程动画：**
- 结果区展示 "AI 正在解析..." 状态面板
- 逐行浮现的结构骨架：
  - "职位名称  ████████" 带 shimmer 动画
  - "技能要求  ██████  ██████  ██████"
  - "核心职责  ████████████"
  - 每条骨架延迟 200ms 依次出现
- 10 秒内未返回则显示 "AI 正在深度解析，请稍候..."

**结果区：**
- 职位名称用金色大字 `--accent`，级别/经验要求/学历用 `el-descriptions`（深色覆写）
- "必备技能"标签：金色半透明底 `--accent-subtle` + 金色文字
- "加分技能"标签：绿色半透明底 + 绿色文字
- "核心职责"：带金色圆点（`●`）列表，行间距舒适
- 底部操作栏：
  - "发送到简历优化"按钮（金色边框，内联图标）
  - "复制结果"按钮（文字按钮）

### 3.3 简历智能优化 ResumeOptimizer

**现有问题：** 三栏布局左侧信息堆砌；匹配结果展示缺乏洞察力；优化历史位置不明显。

**改动：**

**布局调整：**
- 改为两栏：左 1/3（输入区），右 2/3（结果区）
- 左侧：简历文本输入 + JD 选择面板（从历史 JD 中选择）
- 优化历史从左侧移到右侧"匹配度分析"tab 上方，做成横向可滚动时间线卡片组

**输入区：**
- 简历 textarea 高度 12 行
- JD 选择面板：历史列表项，hover 金色边框，选中态金色底 + 左边框
- "开始匹配分析"按钮全宽，金色主按钮

**匹配度分析结果区：**

**评分展示：**
- 大号评分数字（72px，weight 800，颜色根据分数动态变化：≥80 绿色，60-80 金色，<60 红色）
- 评分下方加一个环形进度指示器（SVG ring），视觉上强化"分数"的感知

**差距雷达图：**
- 五维度蛛网图：技能匹配、经验年限、学历匹配、软技能、项目相关度
- 用 Canvas/SVG 绘制，金色线条 + 金色半透明填充
- 每个顶点标注维度名称和分值
- 图表尺寸约 200x200px，放在评分区域右侧

**匹配点/差距点卡片：**
- 匹配点：带原文引用的卡片
  - 标题行：绿色圆点 + 匹配项名称 + 匹配度小百分比
  - 引用行（灰色小字）："JD原文: ..." + "简历原文: ..."
- 差距点同理，但红底色调
  - 每张差距卡片右侧有"改进建议"按钮，点击展开 AI 给出的优化方向
  - 展开区用淡红底 + 建议文字

**一键优化流程：**
- 匹配完成后，"根据匹配结果优化简历"按钮增大
- 点击后进入优化流程，展示三步骨架加载：
  ① "正在搜索相关 JD 信息..."（图标：🔍 → 完成变 ✓）
  ② "正在检索简历匹配片段..."（图标：📋 → 完成变 ✓）
  ③ "正在生成优化版本..."（图标：✨ → 完成变 ✓）
- 每步完成时播放 micro-interaction（图标弹跳 + 颜色变金）

**优化后简历展示：**
- 注释开关（el-switch）集成到顶部工具条
- 简历内容展示在浅米色/淡金渐变背景（模拟纸张感）：`linear-gradient(135deg, #faf8f0, #f5f0e0)`，字体颜色为深灰
- "改动注释"模式：改动处用金色下划线标记，旁边浮动注释气泡
- 底部工具条：复制 / 下载为文本 / 重新生成

**优化历史（时间线卡片）：**
- 显示在"匹配度分析"tab 上方
- 横向排列的卡片组（overflow-x: auto），每张约 180px 宽
- 卡片内容：JD 名称、日期、匹配分数徽章
- 选中态：金色边框 + 金色底纹
- 点击加载历史记录

### 3.4 求职信生成 CoverLetter

**现有问题：** 填表式布局，风格选择缺乏可视化，结果区缺乏"信"的质感。

**改动：**

**布局调整：**
- 从左右分栏改为垂直递进式（向导式）布局
- 上方：信息填写区
- 下方：结果展示区

**信息填写区：**
- 三张横向平铺卡片：JD 文本、简历文本、收信人信息
  - 每张卡片：标题 + 输入区，背景 `--bg-card`
  - 已有内容时卡片标题旁显示 ✓ 图标
- 风格选择改为三张横向选择卡：
  - 正式商务：深色调预览，展示传统商务信件排版片段
  - 亲和自然：暖色调预览，展示更口语化的片段
  - 技术极客：终端风格预览，展示代码/技术感片段
  - 选中态：金色边框 + 金色底纹 + ✓ 图标
  - 每张卡片下方一行说明文字

**生成按钮：**
- 全宽大按钮，金色渐变背景，高度 48px
- 图标：✨ sparkle（MagicStick）
- 文字："生成求职信"
- hover 态：亮度提升 + 微缩放大（transform: scale(1.02)）
- 点击后按钮变为加载态（spinner + "生成中..."）

**生成动画（替代静态加载）：**
- 垂直三步面板，取代原空白加载区：
  ① "🔍 正在分析目标公司需求..."
  ② "📋 正在匹配你的相关经历..."
  ③ "✍️ 正在撰写个性化求职信..."

  - 完成时金色 ✓ + 上一行灰色淡化
  - 动画与后端 SSE（如果支持）或前端模拟进度配合

**结果区：**
- 信纸风格卡片：
  - 背景 `linear-gradient(135deg, #faf8f0, #f5f0e0)`
  - 内阴影模拟纸张质感
  - 文字颜色深棕/深灰（`#2c2416`）
  - 排版模拟真实信件：
    - 顶格称呼："尊敬的 XX 公司招聘负责人："
    - 正文段落缩进
    - 落款右对齐
    - 日期
  - 金色分割线
- 顶部工具条（浮动在信纸上方）：
  - "复制全文"按钮
  - "下载为 .txt"按钮
  - "重新生成"按钮（带确认 dialog）

### 3.5 投递管理 Tracker

**现有问题：** 默认 Element Plus 白底表格；状态统计卡密集但信息量小；新增按钮位置不够突出。

**改动：**

**状态看板管道（替换顶部统计卡）：**
- 横向管道，6 段状态从左到右
- 每段宽度按实际数量比例，颜色金色渐变填充（从浅金到深金）
- 管道上方左侧：总记录数大字 + "条记录"，右侧：平均匹配度（金色）
- 管道下方：每个状态标注具体数字

**状态筛选器：**
- 从 el-select 改为横向 pill 标签组
- 标签：全部 | 待投递 | 已投递 | 初筛中 | 面试中 | 已 Offer | 已拒绝
- 选中态：金色底 + 深色文字
- 默认态：透明底 + `--text-secondary`
- 切换时平滑过渡

**表格：**
- 全面深色化：背景 `--bg-card`，表头 `--bg-deepest`
- 行 hover：背景 `--bg-hover`
- 状态列：保留下拉选择，但 el-select 覆写为深色样式 + 金色聚焦边框
- 匹配度列：从纯数字 tag 改为迷你进度条 + 数字
  - ≥80：绿色进度条
  - 60-80：金色进度条
  - <60：红色进度条
  - 进度条宽度 60px，高度 6px，右侧数字 14px bold
- 操作列：删除按钮改为文字按钮 `--color-danger`，hover 背景红色半透明

**FAB（浮动操作按钮）：**
- 固定在页面右下角（position: fixed, bottom: 32px, right: 32px）
- 金色圆形按钮，56px 直径，box-shadow
- 图标：Plus，白色/深色
- hover 态：放大 1.05 + 光晕增强
- 点击弹出新增投递 dialog

**空态优化：**
- 无数据时，表格区域替换为：
  - 居中插图（SVG 小火箭或文件图标，金色线条风格）

## 五、实施顺序建议

1. **设计 Token（CSS 变量）** — 建立全局样式变量文件，这是所有后续工作的基础
2. **全局框架** — 侧边栏 + App.vue + Element Plus 全局覆写（卡片、按钮、输入框、表格、标签等）
3. **仪表盘** — 全局框架后就可见效果，激励后续开发
4. **投递管理** — 相对简单的 CRUD 页面，验证表格/FAB/空态等全局组件
5. **JD 分析** — 输入+结果左右布局，验证加载动画
6. **简历优化** — 最复杂的页面，验证雷达图/时间线/一键优化流程
7. **求职信** — 信纸风格 + 向导式布局
8. **统一 Review** — 全面检查色彩一致性、间距、动效、无障碍

## 六、技术实现注意事项

- CSS 变量定义在 `src/styles/variables.css`，main.ts 导入
- Element Plus 覆写通过 CSS 变量 + 局部 `:deep()` 实现，避免全局污染
- 字体通过 Google Fonts CDN 或本地引入 Inter + 思源黑体（Noto Sans SC）
- 雷达图使用原生 SVG 或轻量 Canvas 实现，不引入额外图表库
- 骨架屏使用纯 CSS animation + 自定义组件，不额外安装包
- 所有动画使用 `transform` 和 `opacity`，遵循 prefers-reduced-motion
- 金色的 WCAG 对比度验证：金色 `#f0b90b` 在 `#0b0a1a` 底上对比度约 12:1，通过 AAA 标准

## 七、后端 API 依赖项

以下前端设计依赖后端 API 提供额外的字段或结构调整，实施前需与后端对齐：

| 依赖项 | 涉及页面 | 说明 |
|---|---|---|
| 匹配点原文引用 | 简历优化 | 当前 `matched_points` 返回字符串数组，需要扩展为对象数组，包含 `point`（匹配项名称）、`jd_evidence`（JD 原文片段）、`resume_evidence`（简历原文片段） |
| 差距点原文引用 + 改进建议 | 简历优化 | 同上，`gap_points` 需扩展为 `{point, jd_evidence, resume_evidence, suggestion?}` |
| 五维度分项评分 | 简历优化 | 雷达图需要技能匹配、经验年限、学历匹配、软技能、项目相关度五个维度的独立分值。当前 `score_breakdown` 是自由 key 的对象，需约定为固定的 5 个维度 |
| 求职信 SSE 流式（可选） | 求职信 | 生成动画的三步面板当前用前端模拟进度即可。如果后端支持 SSE 返回中间状态，则动画可与实际进度同步，体验更好 |
| 用户姓名获取 | 仪表盘 | 欢迎横幅的个性化问候需要用户名。可在 `/api/health` 或新增 `/api/user` 端点返回，或前端本地存储 |

**注意：** 所有依赖项都有降级方案。如果后端不改，前端可用当前 API 字段做简化版展示，不阻塞 UI 升级。
